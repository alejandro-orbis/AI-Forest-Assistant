# 🗄️ Database Architecture

This document describes the database structure used by **AI Forest Assistant**.

The system uses **PostgreSQL** as the main database and **PostGIS** for geospatial capabilities such as coordinates, locations and future GIS analysis.

---

## 📌 Overview

AI Forest Assistant stores operational data from different workflows:

| Workflow | Main purpose | Tables used |
|---|---|---|
| Core WhatsApp Engine | Incident management, legal queries and operational reports | `forest_incidents`, `pest_cases`, `permits`, `work_reports`, `queries`, `conversation_state` |
| Weather Risk Engine | Wildfire risk monitoring and alerts | `fire_alerts` |
| Metrics & Reporting | Weekly analytics and operational summaries | Reads from all operational tables |

---

## 🌲 `forest_incidents`

Stores general forest incidents such as wildfires, blocked paths, fallen trees or operational issues.

| Column | Type | Description |
|---|---|---|
| `id` | UUID | Primary key |
| `case_id` | TEXT | Human-readable incident identifier |
| `incident_type` | TEXT | Incident type: `INCENDIO`, `INCIDENCIA`, etc. |
| `description` | TEXT | Incident description |
| `priority` | TEXT | Priority level: `ALTA`, `MEDIA`, `BAJA` |
| `reporter_name` | TEXT | Name of the person reporting |
| `reporter_phone` | TEXT | WhatsApp phone number |
| `latitude` | DOUBLE PRECISION | Latitude |
| `longitude` | DOUBLE PRECISION | Longitude |
| `location` | GEOGRAPHY / GEOMETRY | PostGIS point generated from coordinates |
| `parcela` | TEXT | Parcel or area reference |
| `status` | TEXT | Case status |
| `ai_classification` | TEXT | AI classification result |
| `assigned_to` | TEXT | Assigned supervisor or team |
| `metadata` | JSONB | Additional workflow data |
| `created_at` | TIMESTAMPTZ | Creation timestamp |

## 💬 `conversation_state`

Stores temporary conversational state for multi-step WhatsApp interactions.

This is especially useful when a user reports an incident without coordinates and sends the location in a later message.

| Column | Type | Description |
|---|---|---|
| `user_phone` | TEXT | WhatsApp user phone |
| `current_state` | TEXT | Current state, for example `waiting_coords` |
| `pending_case_id` | TEXT | Related pending case |
| `pending_type` | TEXT | Incident type waiting for completion |
| `context_data` | JSONB | Stored context from previous messages |
| `created_at` | TIMESTAMPTZ | Creation timestamp |
| `updated_at` | TIMESTAMPTZ | Last update timestamp |

## 📍 PostGIS Usage

PostGIS is used to support geospatial capabilities.

Current use cases:

- Store coordinates as geospatial points
- Generate locations from latitude and longitude
- Support future GIS queries
- Enable future map-based dashboards
- Prepare the system for spatial analysis

Example trigger:

```sql
CREATE OR REPLACE FUNCTION update_incident_location()
RETURNS trigger AS $$
BEGIN
  IF NEW.latitude IS NOT NULL AND NEW.longitude IS NOT NULL THEN
    NEW.location := ST_SetSRID(ST_MakePoint(NEW.longitude, NEW.latitude), 4326);
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_incident_location
BEFORE INSERT OR UPDATE ON forest_incidents
FOR EACH ROW
EXECUTE FUNCTION update_incident_location();
```

## 📊 Metrics & Reporting

The dashboard workflow reads from the operational tables and generates weekly metrics.

Main metrics include:

- Total incidents
- Incidents by type
- Incidents by priority
- Legal queries
- Fire alerts
- Top locations
- Historical trends

These metrics are exported to Google Sheets and can be used with Looker Studio or other dashboard tools.

## 🛡️ Security Notes

- Do not expose real user data in public repositories.
- Use test/demo data for screenshots.
- Store secrets in environment variables.
- Do not commit `.env` files.
- Sanitize exported n8n workflows before publishing.
- Enable Row Level Security if using the database in a multi-tenant environment.
